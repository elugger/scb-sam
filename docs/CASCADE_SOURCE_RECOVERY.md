2026年11月10日，三个此前缺少可读源码的级联模块已经补入本项目。两台历史训练服务器保留的三个字节码模块SHA一致，均可在各自原环境完成CPU导入。历史消融并非缺少可执行模型；此前的问题是开源整理副本缺少可读源代码。

| `modeling/sam3D_cascade.py` | 第一服务器另一项目及本地历史源码候选 | 编译后完整代码对象与训练字节码一致 |

## 如何核验

使用CPython 3.10.11在内存编译可读源码，与训练Python 3.10.18产生的真实`.pyc`代码对象比较。两者使用相同字节码版本。仅将每一层代码对象的`co_filename`统一为`<source>`，未忽略行号表、指令、常量、函数参数、默认值、标志或嵌套函数。整个模块的marshal字节及所有嵌套代码对象一致。

项目内包含源码SHA和归一文件名后的完整代码对象SHA。公开SHA固定采用marshal序列化版本2，避免版本3/4的对象引用编码受当前进程对象共享状态影响；完整代码对象字段和行信息仍全部比较。可用CPython 3.10再次检查六个发布文件：

```bash
python3.10 -B scripts/verify_cascade_sources.py
```

该命令只编译与校验源码，不导入模型或Torch，不需要训练数据、预训练权重或GPU。训练字节码作为历史证据保存在私有审计档案中，不作为公开项目的二进制运行依赖。公开清单为`CASCADE_SOURCE_VERIFICATION.json`。

## 恢复身份的限制

构建器的历史文件原字节数记录为2761，本次恢复文件为2662字节。编译后的完整代码对象相同，不代表原始注释、空格或编码字节已经找回。不得将这份文件描述为找到了历史原件，也不使用另一项目中同名但逻辑不同的构建器冒充原训练版本。

源码检索覆盖两台相关项目、源代码归档、可访问编辑器历史，以及本地代码与历史会话；未找到准确构建器原件。个别专有格式历史不能直接还原，这些检索限制不影响对本次恢复代码的编译结果比较。

三份底层源文件不含普通注释；其文档字符串作为运行时属性保留，以保持完整编译对象一致。原唯一移出的普通注释说明：`AutoSAMSeg`可由训练器设置coarse entropy门控，以控制coarse到SAM的mask prompt。无注释、无文档字符串的统一训练入口`ours/hp_hq_final.py`保持原SHA与行为。

## 与完整复现的区别

本次解决三个底层模块的源码缺项。没有改变原模型逻辑、冻结训练记录、初始化、数据、评价规则或已取消实验。原训练准备链仍绑定旧源码散列、数据身份、设备与初始化验收，必须在目标机器重新准备并核验，不能把历史`.pyc`散列冒充新`.py`散列或删除校验。

公开项目的干净环境安装、端到端训练与第三方许可核对仍按`READINESS.json`记录。源码验证通过不等于完整开源项目已完成训练复现验收。
